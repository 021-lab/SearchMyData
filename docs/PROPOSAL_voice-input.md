# PROPOSAL: голосовое управление списком

Статус: задача кодеру, 2026-07-23. Ветка `Voice-list-interface` от
`codex-list-interface`.

Голос добавляется поверх существующего списка, не переписывая его.
Оценивать и принимать это предложение можно независимо от остальной работы
над списком.

Стандарт поведения — `docs/INPUT_HANDLING_STANDARD.md` (rev 3.1).
Алгоритм сопоставления цели — `docs/TASK_RESOLVER.md` + `src/resolver.js`.
Этот документ — привязка стандарта к данному репозиторию: адаптеры, имена
полей, порядок работ. **При расхождении с этим документом побеждает
стандарт; всё, что здесь, — привязка, а не переопределение.**

---

## 1. Что есть сейчас

- Список и управление им — работающий модуль (`list-manager.html`, `src/`).
- `src/list-interpreter.js` — **исполнитель**: `execute(state, input)`
  принимает `{command, actId, payload}`, возвращает `{patch,
  actionLogEntry}`, а для видовых команд — `viewMode`/`effect`. Разбора
  текста в нём нет.
- `src/resolver.js` + `src/test_resolver.js` — резолвер цели, прогон
  `node src/test_resolver.js`, 10/10 PASS.
- Интерактивные элементы размечены `agent-action-id`.
- Голосового ввода нет вообще.

## 2. Что предлагается

Добавить **отдельный модуль голосового ввода**, который формирует команду и
передаёт её на исполнение существующему исполнителю. Исполнитель остаётся
единственной точкой изменения состояния и меняется только в объёме §5.

```
жест + речь  →  ПРИЁМ ВВОДА  →  РАСПОЗНАВАТЕЛЬ  →  ИСПОЛНИТЕЛЬ  →  патч
                   новое           новое          существующий
```

Три функции с похожими ролями — не путать:

| Имя | Что делает | Где |
|---|---|---|
| `resolveCommands(text, context, snapshot)` | текст → кандидаты-команды | новый модуль |
| `resolver.resolve(text, rows)` | текст → `One \| Vector \| Empty` | `src/resolver.js` |
| `execute(state, command)` | команда → патч | `src/list-interpreter.js` |

## 3. Модель взаимодействия — коротко

- Долгое удержание в любой точке экрана открывает полноэкранный оверлей.
- Вверху — живая транскрипция. Вверх от пальца — кандидаты, ближайший
  наиболее вероятен. Точка пальца — «как есть». Ниже — отмена.
- Свайп влево по элементу открывает тот же оверлей с прицепленным
  контекстом — идентификатором этого элемента.
- Отпускание = выбор. Команда исполняется только после финального
  транскрипта.

Полное описание, включая пороги, формулу выбора строки и краевые
случаи, — в стандарте §4–§5.

## 4. Адаптер снимка — обязателен

`resolver.js` — эталон и **не переписывается** под форму данных этого
репозитория. Вход приводится адаптером.

Форма элемента в этом репозитории и то, что ждёт резолвер:

| В репозитории | В резолвере | Преобразование |
|---|---|---|
| `id` | `id` | без изменений |
| `line1` | `title` | `title = line1` |
| `status ∈ {Open, Done, Focus, Archive, Pause}` | `status ∈ {open, closed}` | `Done` и `Archive` → `closed`; `Open`, `Focus`, `Pause` → `open` |
| `parentId`, `order`, `line2`, `collapsed`, `tags` | — | не передаются |

Это **обязательное** место: резолвер отбрасывает `closed`/`superseded`
строчными, а в репозитории статусы с заглавной. Без адаптера фильтр не
сработает никогда, и удалённые из работы задачи попадут в кандидаты.

Смысл отображения: `Done` и `Archive` — завершённые, целями команд быть не
должны. `Pause` и `Focus` — рабочие состояния, задача остаётся доступной.

## 5. Что добавляется в исполнитель

| Команда | Класс | Что делает |
|---|---|---|
| `setParent` | мутирующая | `actId` — переносимый элемент, `payload.parentId` — новый родитель. Пересчитать `order` через существующий `nextOrder` |
| `showSearch` | видовая | `payload.query` — запрос; возвращает `viewMode: 'search'` и найденное множество в `effect` |

Два условия, которые нельзя нарушить:

1. **Имя `showSearch`, а не `search`.** Исполнитель опознаёт видовые
   команды по префиксу `show` и отсутствию их в журнале
   (`!String(input.command).startsWith('show') && input.command !==
   'viewItem'`). Команда с именем `search` попадёт в журнал действий и
   нарушит §7 стандарта.
2. **`setParent` обязан отвергать циклы.** Перенос в самого себя или в
   собственного потомка — без патча и без записи журнала. Проверка уже
   есть в файле: функция `descendants(items, rootId)`.

## 6. Куда попадает новая задача без контекста

Спецификация голосового словаря говорит «родитель inbox». **В этом
репозитории выделенного inbox нет.** `addItem` создаёт элемент с
`parentId: null`, то есть в корне.

Решение: «добавь …» без контекста → `addItem` в корень. Отдельную сущность
inbox не заводить — это отдельная задача, которая к голосу отношения не
имеет.

## 7. Что отменяется

Прежний стандарт приёма ввода (rev 2) прямо запрещал то, на чём держится
эта модель: свайп игнорировался как жест, а сдвиг пальца более ~12 px
отменял начатую запись и закрывал оверлей. В rev 3.1 сдвиг — основной
механизм выбора, свайп влево — способ прицепить контекст.

Реализации по rev 2 несовместимы. Брать rev 2 как канон нельзя.

## 9. Этапы

1. `setParent` и `showSearch` в исполнителе, с тестами (§5).
2. Адаптер снимка (§4), с тестом на то, что `Done`/`Archive` не попадают
   в кандидаты.
3. Слой приёма ввода: жесты, пороги, оверлей без распознавания —
   проверяется на заглушке кандидатов.
4. `resolveCommands`: словарь без контекста и с контекстом, ранжирование,
   заморозка порядка, вызов `resolver.resolve` для команд с целью.
5. Фолбэк на модель, тост, поведение при недоступном канале.

Этапы 1–2 не зависят от 3–5 и могут идти параллельно.

## 10. Приёмка

- Прокрутка списка не ломается ни одним из новых жестов.
- Строка под пальцем не подменяется после начала выбора.
- Команда не исполняется на промежуточном транскрипте.
- Команда с незаполненным обязательным слотом не исполняется частично.
- `setParent` не создаёт циклов.
- Видовые команды не создают записей журнала; `showSearch` в журнал не
  попадает.
- Задачи в статусах `Done` и `Archive` не появляются среди кандидатов.
- При недоступном фолбэк-канале речь не теряется и результат отменяется
  одним `undo`.
- Весь путь пользователя проходится автотестом через поле ввода, без
  синтеза речи.
- `node src/test_resolver.js` проходит в CI.
